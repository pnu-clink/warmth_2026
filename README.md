# Warmer Language Models, Different Errors

## Anonymous review artifact

This repository provides research code and text-free numerical data for studying warmth adaptation in four language-model families: Qwen, Phi-4, Llama, and Gemma. The experiments compare original-response supervised fine-tuning (Original-SFT), warm-response SFT (Warm-SFT), and alternative adaptation methods using task accuracy, warmth, pressure resistance, and error profiles.

**Start with the CPU-only reproduction below.** It recomputes selected statistics from the supplied frozen results without downloading a model, calling an LLM judge, or using an API key. This is a partial reproduction artifact, not a complete replay of every experiment or manuscript table. The coverage and missing materials are listed below.

Author names, affiliations, contact information, and identifying repository links are omitted for review. Third-party attribution and upstream benchmark links are retained.

## 1. Quick start: reproduce saved-result statistics

Run the following from the repository root with **Python 3.11 or newer**. A separate virtual environment is recommended; create it outside this folder to keep the distribution unchanged.

```bash
python -B scripts/verify_submission.py
python -m pip install -r requirements-analysis.txt
python -B scripts/test_release_safety.py
python -B scripts/test_numeric_core.py
python -B scripts/reproduce_summaries.py --output ../warmth_review_results
```

The first command checks file hashes, Python syntax, and credential patterns using only the Python standard library. Dependency installation may require internet access. Once NumPy and SciPy are installed, the numerical reproduction runs locally on CPU with no API calls or model downloads.

The output directory must not already exist. Choose a new name for another run; do not delete or overwrite earlier results. Keep outputs outside this repository because the integrity check rejects unlisted files. No benchmark responses or stored labels are regenerated by this command.

This release is a frozen analysis snapshot. Later Finance/Medical judge records are retained separately in `data/annotation/later_runs/` and are not substituted into the primary paired analysis. Later DoRA aggregates and Gemma Medical results are not merged into the supplied 11-cell Steering snapshot. The quick-start command does not reconstruct all manuscript figures, composite-score rankings, or every additional-method result.

## 4. Condition names and error labels

Historical code and column names are retained:

- `base`: Base model; `neutral`: Original-SFT; `warm`: Warm-SFT (LoRA); `dpo`: Warm-DPO (LoRA).
- Original-SFT uses original responses. It is not a cold-persona or emotionally neutralized condition.
- Label `0`: correct; `1`: knowledge error; `2`: logical error; `3`: truncation/length overflow; `4`: calculation error; `5`: generation/format failure; `6`: Other.

The labels describe observed answers, not proven internal causes. Compare conditions on matched question IDs within the same model and benchmark. Raw error-count differences across benchmarks have different denominators. Human label agreement is response-level validation, not annotation of token-level reasoning boundaries.

## 5. Optional fresh model or judge runs

Fresh runs require additional inputs and are separate from the CPU-only reproduction. Begin with [the reproduction map](docs/REPRODUCTION.txt) and [data-access requirements](docs/DATA_ACCESS.txt), then consult [the server-code guide](server_code/README.txt).

- **Training/inference:** obtain authorized model access, compatible GPU dependencies, the specified training/evaluation inputs, and the required adapters. Historical server paths use `WARM_MODEL_ROOT`. Relative inputs still depend on the working directory.
- **Benchmarks:** the Finance, Medical, and SycoBench runners can download their recorded upstream datasets. Data checking can therefore require network access.
- **Judging/rewriting:** install `requirements-api.txt` and use a private `.env` containing `OPENAI_API_KEY`. Full-context judging requires explicit `--execute`; the legacy CSV judge performs paid requests when run. Authentication and the preserved-source `.env` launcher are documented in [AUTHENTICATION.txt](docs/AUTHENTICATION.txt).

Do not run every script to test installation. Some historical scripts have top-level training code or fixed output names; even `--help` is not safe for those scripts. Read the server guide before execution. Use a separate working copy for private inputs, credentials, and new model runs; never upload that copy as the review artifact.

## 7. Availability and interpretation limits

Raw ShareGPT conversations, benchmark question/response text, free-text judge rationales, model weights, and private credentials are not included. Numeric selection IDs do not replace the withheld text needed for fresh training, judging, or KL inference. Redistribution of third-party data has not been assumed merely because review is anonymous.

Steering/DoRA implementation and exact configurations are incomplete in this collection. The historical Docker image digest and complete environment record are also not available. [MISSING.txt](docs/MISSING.txt) and [RELEASE_STATUS.json](RELEASE_STATUS.json) describe these limits. Available numerical comparisons should not be mistaken for an end-to-end implementation of the missing methods.

The manuscript is supplied through the submission system, not this repository. Code and data hashes are listed in [MANIFEST.json](MANIFEST.json); the integrity checker detects later changes.
